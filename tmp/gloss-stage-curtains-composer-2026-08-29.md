Cursor · Stage curtains, desktop-first, Composer as instrument (2026-08-29)

Gloss-only. Not a build lock. Chuck added three Stage experience points. Cursor locked them into the working contract and reconciled them against current board layout.

Keeper Principle held: Stage is a different state of the Workspace — not the same three-panel room with a canvas in the middle.

1. Open curtains
When Workspace enters Stage, Nav and Chronicle remain the same two side panels — they do not become a fourth shell. They behave like open curtains: just enough width to stay reasonably relevant. Stage takes 50–70% of the screen width and is the primary room.

Code truth today: Dialog layout defaults to Nav 15% / center 50% / Chronicle 35%, user-resizable, persisted. Stage currently only replaces the center message zone. The ratios do not change. Entering Stage must change the room, not just the center content.

2. Desktop first
Stage may be designed desktop-first. A basic mobile version may exist. This is an explicit exception to Composer’s earlier mobile-first sheet posture for the Stage experience itself.

Code truth today: desktop uses the three-panel group; mobile already stacks Dialog full-width with Nav drawer and Chronicle overlay. Stage can keep a basic mobile path without driving the desktop design.

3. Composer as instrument above Stage
Composer must be elevated and significantly improved. It is an instrument that can open above the Stage surface — not a bottom-sheet picker covering the Dialog column, and not a Library tree.

Code truth today: KeeperComposerSheet is a mobile-first bottom sheet (`absolute inset-0` over the center panel only). It answers “bring who or what.” The seed already asked Composer to direct creation (WHO / WHAT / WITH / DIRECTION / OUTPUT). Opening above Stage is the spatial contract for that instrument.
